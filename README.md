# Лабораторная работа №3

Каждая лабораторная работа выполняется в отдельной ветке: `lab1`, `lab3` и т. д.
В текущей ветке находится **лабораторная работа №3** — программа из ЛР №1
(разграничение полномочий пользователей на основе парольной аутентификации),
в которую добавлена защита файла с учётными записями шифрованием.

Индивидуальные задания (вариант №5):

- ЛР №1 — наличие цифр и знаков препинания в пароле;
- ЛР №3 — блочный шифр, режим обратной связи по шифротексту (CFB), к ключу
  добавляется случайное значение, хеширование парольной фразы — MD2.

## Требования

| Инструмент | Версия, на которой проверялось |
|---|---|
| Qt 6 Widgets | 6.11.2 |
| `qmake6`, `moc` | из пакета Qt 6 |
| g++ | 16.2.1 (нужен C++17) |
| GNU Make | 4.4.1 |

CMake не требуется — сборка идёт через `qmake6`.

## Сборка и запуск

```bash
qmake6 lab3.pro -o Makefile   # генерация Makefile (один раз)
make                          # сборка
./lab3                        # запуск
```

Пересобрать после правки исходников — достаточно `make`. Заново генерировать
Makefile нужно только после изменения `lab3.pro` (например, при добавлении
нового файла в `SOURCES`/`HEADERS`).

Очистка:

```bash
make clean      # удалить объектные файлы из build/
make distclean  # удалить и Makefile, и исполняемый файл
```

## Файл учётных записей и его защита

Учётные записи хранятся в файле `security.db` рядом с исполняемым файлом.
Файл **зашифрован**; расшифрованное содержимое существует только в оперативной
памяти (`AccountStore::m_data`) и на диск не попадает, поэтому временного файла
с открытыми данными, который нужно было бы удалять, не возникает.

Расшифрованные данные — последовательность записей `AccountType` фиксированного
размера (36 байт):

| Поле | Тип | Смещение | Назначение |
|---|---|---|---|
| `UserName` | `char[20]` | 0 | имя учётной записи |
| `PassLen` | `int` | 20 | длина пароля |
| `UserPass` | `char[10]` | 24 | пароль |
| `Block` | `bool` | 34 | блокировка администратором |
| `Restrict` | `bool` | 35 | включены ограничения на пароль |

Формат файла на диске:

```
соль (11 байт) | шифротекст (столько же байт, сколько в открытых данных)
```

### Алгоритмы (вариант №5)

| Параметр | Значение |
|---|---|
| Тип шифрования | блочный, RC2 (блок 8 байт, ключ 128 бит) — `CALG_RC2` |
| Режим | обратная связь по шифротексту, CFB с порцией 8 бит (`CRYPT_MODE_CFB`) |
| Добавление случайного значения к ключу | да — 11 случайных байт (соль) |
| Хеширование | MD2 — `CALG_MD2` |

Ключ вырабатывается так: `ключ = MD2(соль ‖ парольная фраза)`, 16 байт.
Соль берётся из генератора случайных чисел операционной системы, **новая при
каждой записи файла**, и хранится в его начале открыто (секретной она не
является — её задача в том, чтобы одинаковая фраза давала разные ключи и
шифротексты). Начальный вектор CFB нулевой, как в CryptoAPI по умолчанию; так
как ключ при каждой записи новый, повторного использования пары «ключ — вектор»
не происходит. CFB с порцией 8 бит не требует дополнения данных до размера
блока.

Функции CryptoAPI Windows (`CryptCreateHash`, `CryptDeriveKey`, `CryptEncrypt` и
т. д.) недоступны под Linux, поэтому MD2 и RC2 реализованы в программе
самостоятельно по RFC 1319 и RFC 2268. Реализации проверены по эталонным
векторам и сверены с независимой библиотекой (pycryptodome) на случайных
данных.

### Порядок работы с файлом

1. **Первый запуск** (файла нет): программа просит задать парольную фразу
   (с подтверждением), создаёт файл с учётной записью `ADMIN` (пустой пароль) и
   шифрует его.
2. **Последующие запуски**: окно «Расшифрование базы данных» запрашивает
   парольную фразу, из неё вырабатывается ключ, файл расшифровывается в память.
3. **Проверка фразы**: фраза считается верной, если в расшифрованных данных
   есть учётная запись администратора `ADMIN` (при неверной фразе получается
   случайный набор байт).
4. **Неверная фраза или отказ от ввода** — выдаётся сообщение и программа
   завершается.
5. **Завершение работы** (любым способом, включая «Выход» и три неверных ввода
   пароля): данные шифруются заново с новой солью, прежнее содержимое файла
   предварительно затирается нулями, затем записывается новое.
6. Окно запроса фразы — не постоянная форма: оно создаётся перед запросом и
   уничтожается сразу после него, поле ввода очищается.

Фраза и ключ не сохраняются на диск; в памяти ключ затирается после выработки,
а расшифрованные данные и фраза — при завершении работы.

Посмотреть содержимое файла (должен быть набор случайных байт):

```bash
hexdump -C security.db
```

Сбросить состояние программы к первому запуску (**все учётные записи будут
потеряны**, а при утрате парольной фразы восстановить файл невозможно):

```bash
rm security.db
```

## Как пользоваться программой

1. Запустить программу, ввести парольную фразу от файла учётных записей (при
   первом запуске — задать её), нажать **«Вход в систему»**.
2. Первый вход — имя `ADMIN`, поле пароля оставить пустым. Программа
   потребует задать пароль и подтвердить его повторным вводом.
3. В режиме администратора доступны все команды меню **«Пользователи»**:
   - *Смена пароля* — со вводом старого пароля;
   - *Новый пользователь* — имя должно быть непустым и уникальным, учётная
     запись создаётся с пустым паролем;
   - *Все пользователи* — таблица всех учётных записей; флажки «Блокировка» и
     «Парольное ограничение» применяются кнопкой **«Сохранить»**;
   - *Выход*.
4. Обычному пользователю доступны только *Смена пароля* и *Выход*, остальные
   команды заблокированы.
5. **«Справка → О программе»** показывает автора и формулировку варианта.

Ограничения работы с паролями:

- символы пароля на экране всегда заменяются на `*`;
- три неверных ввода пароля подряд завершают работу программы;
- заблокированный администратором пользователь войти не может;
- учётную запись `ADMIN` заблокировать нельзя — иначе система осталась бы без
  администрирования;
- длина имени ограничена 19 байтами, длина пароля — 9 байтами (кириллица в
  UTF-8 занимает по два байта на символ).

## Ограничение на пароль (вариант №5)

При включённом для учётной записи признаке ограничений новый пароль обязан
содержать **и цифру, и знак препинания**.

Знаки препинания: `.` `,` `;` `:` `-` `!` `?` `(` `)` `"` `'`

Список взят из указаний по выполнению лабораторных работ. Функция `ispunct()`
намеренно не используется: она относит к знакам препинания и знаки
арифметических операций (`+` `*` `/` `%`), которые в задании выделены в
отдельную категорию.

Примеры: `1234` и `abc.` отвергаются, `1234.` и `Пароль1!` принимаются,
`1+2` отвергается (`+` — арифметика), `1-2` принимается (`-` входит в список).
